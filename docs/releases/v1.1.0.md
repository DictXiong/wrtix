## wrtix 1.1.0

### Changes

- Concise UCI declarations, router configuration import and selective SOPS encryption.
- Extensible runtime secret providers and separate prerequisite package preparation.
- Optional configuration diffs for verification, remote previews, deployment,
  confirmation and rollback. Secret-derived files stay private; JSON results keep
  their existing format.
- Confirmation SSH calls use the transaction's remaining lease, allowing bounded
  required checks to complete without changing the target deadline.
- Per-service `checkRunning` policy, enabled by default. Explicitly disabling it
  separates process-health acceptance from managed configuration and enablement;
  service actions and required extension checks still run.

### Usage

Upgrade the controller and agent while no transaction is pending. Pin the Nix
input to `github:DictXiong/wrtix/v1.1.0` and install the signed agent APK using the
[installation instructions](https://github.com/DictXiong/wrtix/blob/v1.1.0/feed/README.md).
Agent installation preserves network settings and existing login credentials.
The controller verifies the matching agent capability contract before deployment.

```sh
openwrt-rebuild verify --flake .#site --device router --diff
openwrt-rebuild switch --flake .#site --device router --diff
```

### Validation and boundaries

The release workflow gates publication on Nix regressions, the pinned official
SDK's signed noarch APK and official OpenWrt 25.12 VM package/transaction acceptance.
OpenWrt 25.12 with APK 3 is the accepted package environment; opkg has simulated
coverage. Prerequisite installation and firmware upgrades remain separate from
configuration rollback. Hardware-specific wireless and forwarding validation
belongs to the consuming firmware or profile.
