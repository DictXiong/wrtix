## wrtix 1.2.0

### Changes

- Normal `switch`, `test` and `deploy` can change an enrolled device's configuration
  ID. The controller warns on stderr and continues without a rename option,
  initialization or an interactive confirmation.
- Remote previews report the proposed ID change without applying it. Package
  preparation also warns, but leaves the registered ID unchanged.
- Identity and ownership changes share the existing configuration transaction.
  Confirmation accepts the new identity; rollback restores the old identity and
  configuration. Strict SSH authentication, fresh baseline checks, required runtime
  checks and rollback deadlines remain enforced.

### Usage

Pin the Nix input to `github:DictXiong/wrtix/v1.2.0` and upgrade to the matching
signed `wrtix-agent` package using the
[installation instructions](https://github.com/DictXiong/wrtix/blob/v1.2.0/feed/README.md).
Finish pending transactions before upgrading. The controller rejects an older
1.1.1 agent contract rather than silently bypassing it.

Select the new device definition with the existing router's `--target-host`.
Existing `--post-switch-host` and `--ask-post-switch-host` options handle address
changes, including DHCP after a planned MAC reboot.

### Validation and limits

Focused regressions, official OpenWrt transaction tests and physical-device checks
covered ID changes, confirmation, repeated noop deployment and rollback. A forward
MAC change with a guarded reboot and DHCP handoff was also verified. This does not
claim a complete reverse-MAC reboot matrix or a fix for earlier intermittent VM
reboot failures, whose root cause remains unknown.

Publication requires the normal Nix checks, a fresh signed SDK package and the
complete official OpenWrt VM acceptance suite.
