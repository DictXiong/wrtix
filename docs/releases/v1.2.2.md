## wrtix 1.2.2

### Changes

- Ordinary `switch`, `test` and `deploy` can change an enrolled device's logical
  ID within the normal transaction. A stderr warning identifies the change;
  no rename option or mandatory prompt is needed.
- Fresh-baseline checks, strict SSH authentication, confirmation deadlines and
  rollback protection remain in place. Controller, agent and capability contract
  are unchanged from 1.2.1.

### Usage

Pin the Nix input to `github:DictXiong/wrtix/v1.2.2` and install the matching signed
`wrtix-agent` APK using the
[installation instructions](https://github.com/DictXiong/wrtix/blob/v1.2.2/feed/README.md).
Finish pending transactions before upgrading. The older 1.1.1 agent contract is
not silently accepted by the current controller.

### Validation and limits

The targeted official-VM MAC change/restore sequence passed with two real guest
reboots and the original identity, MAC and transaction confirmation checks.
Publication additionally requires the normal Nix checks, signed SDK package,
complete VM transaction suite and package lifecycle gates.

Earlier intermittent CI reconnect failures remain unexplained; this version does
not claim a QEMU or guest-runtime fix. The VM fixture loads the exact kernel from
its pinned official image directly and retains its root disk and normal boot
arguments. GRUB loading and layout are not covered by that fixture.
