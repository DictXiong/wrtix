## wrtix 1.2.1

### Changes

- The official OpenWrt VM fixture loads the exact kernel extracted from its pinned
  disk image directly. Kernel size, SHA-256 and boot header are checked before use;
  the root disk, normal boot arguments and complete transaction checks are retained.
- This avoids the GRUB loading path observed during a failed emulated reboot.
  GRUB loading and layout are no longer covered by this fixture. This is a test
  workaround, not a GRUB/QEMU or product runtime fix.
- Controller, agent and capability contract are unchanged from 1.2.0. Ordinary
  `switch`, `test` and `deploy` support enrolled ID changes with a stderr warning,
  no rename option or mandatory prompt, and the original rollback protection.

### Usage

Pin the Nix input to `github:DictXiong/wrtix/v1.2.1` and install the matching signed
`wrtix-agent` APK using the
[installation instructions](https://github.com/DictXiong/wrtix/blob/v1.2.1/feed/README.md).
Finish pending transactions before upgrading. The controller requires the matching
agent contract; the older 1.1.1 contract is not silently accepted.

### Validation and limits

The release retains the standard Nix checks, signed SDK package and complete
official VM controller and package lifecycle gates. The fixture keeps real guest
reboots and the original authentication, boot/MAC readback, confirmation, timeout
and rollback requirements. It does not replace downstream hardware acceptance or
resolve the underlying cause of earlier disk-boot failures.
