## wrtix 1.1.0 rc 1

### Changes

- Concise UCI declarations through `wrtix.lib.uci`, alongside explicit section definitions.
- `openwrt-rebuild import` captures a running router into a reusable Nix project.
  Import is plaintext by default; selected options can be encrypted with SOPS.
- `prepare-packages` installs missing prerequisites separately from configuration
  transactions. Missing-package errors include a copyable preparation command.
- Extensible runtime secret providers, with lookup caching, bounded execution and
  failure handling that prevents deployment when a required secret is unavailable.

### Usage

Upgrade the controller and agent together while no transaction is pending. Pin
the Nix input to `github:DictXiong/wrtix/v1.1.0-rc.1` and install the attached signed
agent APK using the [installation instructions](https://github.com/DictXiong/wrtix/blob/v1.1.0-rc.1/feed/README.md).
Agent installation preserves existing network settings and login credentials.

```sh
openwrt-rebuild prepare-packages --flake .#site --device router
openwrt-rebuild switch --flake .#site --device router
```

See the [usage guide](https://github.com/DictXiong/wrtix/blob/v1.1.0-rc.1/docs/usage.md)
for import, selective encryption and provider examples. Package installation sits
outside configuration rollback.

### Validation

The candidate passed x86_64 Nix checks, official OpenWrt 25.12.0 VM workflow tests
and physical ARM64 workflow acceptance, including timeout rollback and noop
deployment. Physical package tests used a temporary signed local repository.
Release CI additionally builds the signed APK with the pinned official SDK and
accepts that artifact in the official VM before publishing.

This is a release candidate. OpenWrt 25.12 with APK 3 is the accepted package
environment; the opkg path currently has simulated coverage. Further observation
will precede a stable 1.1.0 release.
